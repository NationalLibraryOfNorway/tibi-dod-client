# One session manager owns initialisation and relogin; conformance runs bypass it

All Session handling that ordinary commands need, meaning reuse of the Session file, the Initialisation sequence and the single relogin attempt after a `noActiveSession` fault, lives in one application-level session manager that wraps the port. The port never logs in again or retries (ADR 0004), and the conformance runner never uses the session manager: it opens its own ports and Sessions, so a fault is seen as data instead of being hidden by a relogin. Ephemeral mode is the same session manager with an in-memory store, not a separate code path. We rejected relogin in the port because it would hide the very behaviour a conformance test must observe, and rejected a decorator or a shared retry helper used by both because the two consumers want opposite policies and a shared mechanism would need a flag to switch it off.
