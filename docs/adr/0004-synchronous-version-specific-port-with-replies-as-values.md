# The port is synchronous and specific to DODP v1, and Service answers are returned as values

The port towards a Service is a synchronous interface with one typed method per DODP v1 operation, bound to one Service URL and at most one Session, and its domain models mirror the specification's types one to one. Everything the Service actually answered, including faults and answers that contradict the specification, is returned as a `Reply` value; only the cases where the test could not be evaluated (no answer, not SOAP, redirect across a host boundary) are raised as `TransportError`. This follows the Outcome model: values can become PASS or FAIL, exceptions become ERROR. Version-neutral parts (the `Reply` envelope, the exchange record, Observations, the opaque session state, transport errors) live in a shared kernel, and DODP v2 is added as a sibling port rather than by widening this one. DODP v2.0.x reuses the v1 namespace with different element shapes, new operations and more fault types, so a shared port would have to fake a common model.

We rejected an async port because the protocol is sequential over one Session and an async port would force `async` through the application layer, the in-memory adapter and every test; Textual runs the calls in thread workers instead. We rejected exceptions for faults because in a test client a fault is ordinary data, and a version-neutral port because nothing is known about v2 that justifies the abstraction.

Amended by ADR 0008: `fetch_resource` streams to a sink and non-2xx statuses are `Deviation`s, and every `Deviation` carries a Spec reference.
