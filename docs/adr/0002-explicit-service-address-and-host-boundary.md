# Never guess the Service endpoint; credentials and cookies never cross a host boundary

DODP v1 has no discovery mechanism and no path convention, so `dod` takes the Service address only from explicit inputs (`--url`, `--wsdl`, or an Environment that holds one of them) and never probes paths during login. Guessing lives in a separate `dod discover` command that sends no credentials. Credentials and cookies are sent only to the host the user named: a WSDL whose `soap:address` has a different host, port or scheme is refused unless the user passes `--trust-host`, and redirects across a host or scheme boundary are rejected. We rejected a single `--url` that the client interprets (SOAP, then `?wsdl`, then known paths) because it can send a password to an address the user never chose, and it hides what was tried.
