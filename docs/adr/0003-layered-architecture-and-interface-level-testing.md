# Layered architecture with ports and adapters; tests exercise module interfaces only

`dod` is split into domain models, application logic, infrastructure for talking to a Service, and presentation (CLI and TUI), following clean architecture and ports and adapters: dependencies point inwards and the application reaches the Service only through a port. Automated tests exercise each module through its public interface only, never its internals, and a shared contract test suite for the port runs against every adapter (an in-memory one and the HTTP one, the latter against a fake Service on localhost) so they cannot drift apart. The dependency direction is enforced automatically with `tach` (MIT). We rejected tests that mock internals or reach across modules because they pin the current implementation and make the architecture expensive to change, for example when adding DODP v2.
