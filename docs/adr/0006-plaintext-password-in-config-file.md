# Store the password in plaintext in the configuration file, no keyring or command in v1

An Environment may hold the `username` and `password` for its Service in the configuration file, as plaintext. `dod` refuses to read a configuration file that contains a `password` while it is readable by group or others on Linux and macOS (anything but `0600`), as `ssh` does, and masks the value in `dod config show` and in error messages. Passwords can also be given with `--password-stdin` or a prompt; there is no environment variable. This extends the plaintext model of ADR 0001 from a revocable session cookie to a long-lived password, which is a larger exposure, accepted because the alternatives cost more than v1 can carry. We rejected OS keyrings (heavy dependency, fail headless), a `password_command` that runs a user-chosen program such as `pass` or `op` (the safest option, but platform-specific commands and an executable configuration file make it too complicated for v1), and per-Environment password variables (extra naming and normalisation rules for little gain over `--password-stdin`). Revisit with `password_command` if the plaintext exposure becomes a problem.
